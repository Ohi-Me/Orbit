# ---------------------------------------------------------------------------
# Deployment requirements (Render, Fly, Railway, any small container).
#
# WHY THIS FILE EXISTS, SEPARATE FROM requirements.txt
# requirements.txt installs torch, transformers, sentence-transformers and
# mlflow. Together those are several GB and will exhaust the memory and disk of
# a small instance during the build. They are genuinely optional: the platform
# probes for each at runtime and falls back to a documented, labelled
# substitute, then reports "fidelity: degraded" at /api/health so nothing is
# silently misrepresented.
#
# WHAT YOU LOSE WITH THIS FILE
#   deep learning        LSTM and Transformer are skipped; logistic regression
#                        and XGBoost still train and compete
#   neural embeddings    RAG retrieval falls back to BM25 (lexical only)
#   cross-encoder rerank unavailable
#   FinBERT sentiment    falls back to the labelled keyword baseline
#   MLflow tracking      no-ops cleanly
#
# WHAT STILL WORKS
#   The whole pipeline: real data ingestion, point-in-time features, purged
#   walk-forward validation, HAC-corrected inference, cost-aware backtesting,
#   risk decomposition, portfolio construction, the critic and the approval
#   gate. Verified by importing the app with every heavy package blocked.
#
# To deploy at full fidelity, use requirements.txt on an instance with at least
# 4 GB of RAM and 10 GB of disk, and set a persistent HF_HOME cache.
# ---------------------------------------------------------------------------
